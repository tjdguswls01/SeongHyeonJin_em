Kernel 2는 무엇인가

Mastercard 전용 L2 로직

Entry Point가 Mastercard AID를 선택한 뒤, 카드와 단말기 사이의 거래 규칙을 실행하는 브랜드별 처리 계층이다.

표준의 역할

카드 명령 순서, 데이터 해석 방식, 승인·거절·온라인 전환 결과를 동일한 기준으로 맞추는 규격이다.

정리: Kernel 2는 Mastercard 비접촉 결제의 판단 엔진이다.

DEK와 DET가 중요한 이유

DEK

Kernel이 추가 데이터나 의사결정용 정보를 Terminal에 요청하는 신호다. 실시간 데이터 교환 창구 역할이다.

DET

Terminal이 Kernel에 필요한 데이터를 넘기거나 온라인 응답, 제어 정보를 제공하는 신호다.

정리: Kernel 2는 거래 도중에도 단말기와 데이터를 주고받으며 판단을 보정한다.

Reader Database의 큰 그림

영구 데이터

AID 목록, 공개키, 메시지, 리더 설정처럼 여러 거래에 걸쳐 유지되는 데이터다.

M, S, P, D, K가 각자 필요한 데이터를 보유하되, Kernel은 TLV 중심 구조를 가장 많이 활용한다.

Kernel 2의 중심은 TLV Database다

TLV 방식

모든 주요 데이터는 Tag-Length-Value 구조로 저장한다. 태그만 보면 데이터 의미를 즉시 식별할 수 있다.

거래 시작 시 영구 템플릿에서 현재 거래용 인스턴스를 만들고, 카드·단말기 응답으로 계속 갱신한다.

의미: Kernel 2는 상태 변수보다 TLV 데이터베이스를 중심으로 동작한다.

CVM과 위험관리의 결합

CVM 판단

금액 기준, 카드 요구조건, 단말기 기능을 비교해 No CVM, Online PIN, CDCVM 등을 결정한다.

GPO는 거래 모드와 읽기 계획을 정한다

AIP

SDA·DDA·CDA, CVM, Terminal Risk Management, On-device CVM, EMV Mode, RRP 지원을 비트로 나타낸다.

모드 결정

카드 AIP의 EMV Mode 비트와 Kernel Configuration을 비교한다. EMV Mode를 사용할 수 없고 Mag-Stripe를 지원하면 Mag-Stripe 경로를 선택한다.

AFL·IDS 객체

AFL은 READ RECORD 순서를 정한다. IDS 지원 데이터는 GPO Format 2의 DS 관련 객체로 별도 전달된다.

정리: AIP 하나가 모든 기능을 표시하는 것이 아니라 설정과 응답 객체를 함께 보아야 한다.

SDS는 결제 명령과 분리된 저장 경로다

Standalone Data Storage

Data Exchange로 받은 Tags To Read와 Tags To Write에 따라 GET DATA와 PUT DATA를 실행해 카드 데이터를 읽고 쓴다.

적용 범위

EMV Mode의 선택 기능이며 Mag-Stripe Mode에는 적용되지 않는다. 읽기를 먼저 끝낸 뒤 쓰기를 수행한다.

포인트: SDS는 독립 APDU를 추가하고 IDS는 기존 GPO·GENERATE AC에 저장 처리를 통합한다.

Kernel 2는 상태 기계로 움직인다

초기 상태

ACT를 기다리며 거래용 데이터베이스를 준비한다.

중간 상태

GPO, READ RECORD, ODA, Generate AC, IDS, 복구 로직이 각 상태에서 순차 실행된다.

Outcome을 조립해 OUT Signal로 반환하고 다음 거래를 위한 초기 조건으로 돌아간다.

핵심: 표준은 함수 목록보다 상태 전이 규칙으로 거래 동작을 고정한다.

Kernel 2 이해의 핵심 정리

구조 관점

5개 프로세스와 Signal 체계, TLV Database, 상태 기계가 Kernel 2의 골격을 이룬다.

기능 관점

Mag-Stripe와 EMV 이중 모드 위에 ODA, CVM, Generate AC, SDS, IDS, Torn Recovery가 얹힌다.

한 문장: Mastercard Kernel 2는 비접촉 거래를 데이터 중심 상태 기계로 해석하고, 결과를 표준화된 Outcome으로 반환한다.
