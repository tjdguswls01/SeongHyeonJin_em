# Visa Kernel 3의 이해 발표 대본

## 슬라이드 1. 제목
이번 발표는 Visa Kernel 3가 짧은 탭 안에서 카드의 거래 판정을 확보하고, 이를 검증해 Outcome으로 바꾸는 구조를 설명한다.

## 슬라이드 2. Visa Kernel 3는 무엇인가
Kernel 3는 단순 통신 모듈이 아니라 Visa 비접촉 결제용 L2 판단 엔진이다.

## 슬라이드 3. 결제 단말기 구조에서 Kernel 3의 위치
Kernel 3는 상위 애플리케이션과 하위 RF 통신 사이에서 거래 의미를 정리하는 계층이다.

## 슬라이드 4. qVSDC의 의미
qVSDC는 짧은 탭 시간 안에 필요한 데이터를 모으고 이후 단말이 후속 판단을 이어 가는 Visa 비접촉 방식이다.

## 슬라이드 5. qVSDC가 중요한 이유
빠른 데이터 확보와 후속 로컬 판단이 분리된다는 점이 Kernel 3 구조의 출발점이다.

## 슬라이드 6. 거래 흐름 전체 보기
전체 흐름은 AID 선택, PDOL과 TTQ 준비, GPO, 필요한 경우의 READ RECORD, 검증과 Outcome 순서이다. Kernel 3는 일반 거래에서 별도 GENERATE AC를 보내지 않고 GPO 응답에서 Cryptogram을 받는다.

## 슬라이드 7. 거래 시작 시 단말이 준비하는 값
거래 금액, 통화, 환경 정보, 단말 능력 같은 값이 처음부터 준비되어야 한다.

## 슬라이드 8. 왜 입력값 정확성이 중요한가
이 값들이 그대로 PDOL과 GPO에 들어가므로 초기 데이터 품질이 전체 거래 품질을 좌우한다.

## 슬라이드 9. PPSE와 후보 선택
카드가 제공한 애플리케이션 목록과 단말 허용 목록을 비교해 적합한 경로를 찾는다.

## 슬라이드 10. 최종 SELECT와 얻는 정보
최종 SELECT 이후 FCI와 PDOL이 확보되며 본격적인 커널 실행 준비가 끝난다.

## 슬라이드 11. TTQ의 정의
TTQ는 단말이 어떤 기능을 지원하는지 카드에 선언하는 비트 정보이다.

## 슬라이드 12. TTQ가 판단에 미치는 영향
TTQ는 EMV Mode, 온라인 처리, CVM 지원 능력과 이번 거래의 CVM Required 여부를 카드에 전달한다. 이 값이 실제 단말 능력과 달라지면 카드의 CTQ와 거래 판정도 잘못된다.

## 슬라이드 13. CTQ의 정의
CTQ는 카드가 이번 거래에서 원하는 처리 조건을 표현하는 비트 정보이다.

## 슬라이드 14. TTQ와 CTQ의 관계
TTQ가 단말 능력이라면 CTQ는 카드 요구이며 실제 거래는 둘의 교집합에서 결정된다.

## 슬라이드 15. PDOL 조립과 GPO 요청
카드가 요구한 태그와 길이에 맞춰 단말 값을 조립하고 그 결과를 GPO에 싣는다.

## 슬라이드 16. GPO 응답이 거래 방향을 먼저 담는다
GPO 응답에는 Cryptogram과 CID, IAD, CTQ가 들어온다. AIP는 카드 능력을, AFL은 추가로 읽을 레코드를 나타낸다. 따라서 Visa Kernel 3의 GPO는 단순 준비 명령이 아니라 카드 판정 결과를 받는 핵심 단계이다.

## 슬라이드 17. AFL이 있을 때만 READ RECORD를 수행한다
AFL이 있으면 지시된 레코드에서 서명과 추가 데이터를 보완한다. AFL이 없으면 곧바로 Card Read Complete로 이동한다. GPO와 레코드 전체에서 필수 데이터 누락과 중복도 확인한다.

## 슬라이드 18. 카드를 먼저 떼고 단말 처리를 계속한다
Card Read Complete는 카드와의 데이터 교환이 끝났음을 뜻한다. 이 시점부터 사용자는 카드를 뗄 수 있고, 단말은 확보한 데이터로 제한 검사, fDDA, CVM과 온라인 메시지 구성을 계속한다.

## 슬라이드 19. Processing Restrictions와 fDDA
Processing Restrictions는 만료일과 사용 조건을 검사한다. fDDA는 카드가 만든 동적 서명을 검증해 카드 복제와 데이터 변조 위험을 확인한다.

## 슬라이드 20. TTQ와 CTQ로 CVM을 확정한다
No CVM, Consumer Device CVM, Online PIN, Signature 중 실제 사용할 방법은 카드 요구와 단말 능력, CVM Required 조건을 함께 보고 정한다.

## 슬라이드 21. GPO 응답의 Cryptogram을 해석한다
CID는 AAC, ARQC, TC 방향을 나타낸다. Application Cryptogram과 IAD, ATC는 거래 데이터와 카드 상태를 결합해 발급사가 검증할 수 있는 온라인 자료를 만든다.

## 슬라이드 22. AAC, ARQC, TC의 차이
AAC는 오프라인 거절, ARQC는 발급사 온라인 승인 요청, TC는 오프라인 승인 결과이다. 이 방향은 GPO 응답에서 이미 카드가 정해 돌려준다.

## 슬라이드 23. IDS와 Issuer Update는 기본 거래의 확장이다
IDS는 EXTENDED GPO와 전용 레코드를 이용해 카드 저장 데이터를 처리한다. Issuer Update는 온라인 거래 뒤 두 번째 Presentment에서 인증과 스크립트를 같은 카드에 전달하는 선택 기능이다.

## 슬라이드 24. Outcome과 최종 단말 동작
Kernel은 Outcome을 만들고 상위 앱은 그 결과를 화면, 부저, 승인 통신 같은 실제 동작으로 바꾼다.

## 슬라이드 25. TNP-10 소스에서의 구현 위치와 결론
소스에서는 Tag 9F66으로 TTQ를 설정하고 Tag 9F6C와 TTQandCTQ 함수로 카드 요구를 해석한다. 선택, PDOL, GPO, CID 처리 지점이 나뉘어 있어 표준의 입력과 판정 흐름을 추적할 수 있다.
